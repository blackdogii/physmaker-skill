# 核准流程分支

高風險操作（刪除、合併、覆蓋、衝突、規則升級、改變既有資料夾結構）一律不得直接執行，依執行情境走以下分支之一。

## 互動對話中（使用者當下在場）

直接在回覆中列出四項資訊，等待明確同意後才執行；未獲同意時保留原樣，不得自行選一個折衷方案悄悄頂替：

1. 原始內容與位置
2. 建議修改
3. 修改理由
4. 影響範圍

## 排程／背景執行（無人即時應答，例如每日 consolidate 自動化）

**一律不得詢問等待**，直接把上述四項資訊寫入 `40-決策紀錄/待小威確認.md`，原內容維持不動，不得假設同意、不得靜默跳過不記錄。這是預設行為，不是備援選項。

`待小威確認.md` 條目固定格式：

```markdown
## YYYY-MM-DD：<主題>
- 原始內容與位置：...
- 建議修改：...
- 理由：...
- 影響範圍：...
- 來源：[[收件匣筆記或任務]]
```

## 兩種情境共同原則

- 不得靜默覆蓋舊決策；新舊內容、來源與日期都要保留。
- 無法判定風險等級時，一律當作高風險處理，走上述分支，不得自行降級成純新增處理。
- 機密相關內容（`60-機密/`）不適用本流程——不讀取、不轉錄、不建議修改，完全排除在外。
