# Consolidate 模式驗收細節

## 逐篇處理判斷樹

對 `01-收件匣/` 裡每一篇筆記（README.md 除外）：

1. 讀 frontmatter 的 `category`，對應到目標正式檔案（見 `classification-taxonomy.md`）。
2. 目標檔案裡搜尋是否已有語意相同內容：
   - 有 → 判定「重複」，不寫入正式檔案；筆記仍視為「已處理」，移入來源封存。
   - 沒有，且不會跟既有內容衝突 → 判定「純新增」，併入正式檔案，用 `## YYYY-MM-DD：主題` 分段；移入來源封存。
   - 會跟既有內容衝突、需要覆蓋或合併既有段落 → 判定「需核准」，套用 `approval-flow.md` 的排程分支寫入 `待小威確認.md`；**筆記留在收件匣，不移動**，並將筆記 frontmatter 的 `status` 更新為 `待小威確認`。
3. 若某篇筆記本身標記語意重複於另一篇「本次也在處理」的收件匣筆記，兩篇合併只處理一次，避免正式檔案重複段落。

## 移動來源的規則

- 只有判定「重複」或「純新增」（已成功寫入正式檔案）的筆記才移到 `90-每日復盤/來源封存/YYYY-MM-DD/`。
- 「需核准」的筆記保持原地，不移動、不改檔名，等下次 consolidate 執行時重新檢查是否已被核准處理。

## 每日復盤摘要要包含

- 新增長期記憶（依分類條列）
- 專案進度（若有）
- 已確認決策（若有）
- 待小威確認（本次新增的 + 提醒既有未解決項目）
- 來源清單（wikilink 連到來源封存位置）

格式比照既有 `90-每日復盤/YYYY-MM-DD.md`。

## 完成後必須核對

- [ ] 收件匣裡沒有被跳過、沒處理到的筆記（每一篇都要有明確結果）
- [ ] 已合併的筆記都能在來源封存資料夾找到
- [ ] `每日復盤索引.md` 有新增今天這篇的連結
- [ ] 若有新專案／新決策主題，`專案索引.md`／`決策索引.md` 已同步更新
- [ ] `待小威確認.md` 掃過一輪，看有沒有舊項目被這次處理順便解決
- [ ] 沒有把機密值、完整終端輸出、可由 Git 重建的程式碼寫進正式檔案
